# Sia design documents

Sia should make it easier to get useful code from an AI agent. Keep repository knowledge and project expertise close
to the code; keep ordinary task handling simple. Add a process only when its benefit exceeds its cost to developers.

- [Product](product.md): purpose and what earns a place in Sia.
- [Protocol](protocol.md): activation and instruction boundaries.
- [Orchestration](orchestration.md): coding, requested plans, optional resume, Forge, and workers.
- [Repository knowledge](repository-knowledge.md): useful documentation and freshness.
- [Extensions](extensions.md): project definitions, catalogs, and overrides.
- [Writing examples](writing-examples.md): concrete answers and plans.
- [Integration](integration.md): host bridges and installation.
- [Source layout](source-layout.md): managed and project-owned files.
- [Prompt caching](prompt-caching.md): optional performance considerations.
- [Host matrix](host-matrix.md): dated observations and certification limits.
- [Implementation and evaluation](implementation.md): checks and real coding comparisons.

The installed protocol and effective definitions guide execution. These docs describe the product; they do not add
another layer of agent instructions. Changes should be consistent across source prompts, installation, docs, and tests.
