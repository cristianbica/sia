# Review

Establish the requested target and base revision. Use relevant repository context and the effective code-review skill;
load testing guidance if validation evidence needs examination. Keep source, docs, plans, and external state read-only.
Do not scan historical plans for a likely request. Follow only explicitly authorized plan paths.

Trace the changed behavior far enough to assess the findings. Report concrete impact with source locations, prioritized
by severity, followed by checks and meaningful limitations. Do not imply proof of correctness from a clean review.
Independent review can help, but workers are optional. Keep the assignment bounded if delegating and report its actual
isolation. Recommend necessary fixes without implementing them. An interrupted review has no resumable artifact.
