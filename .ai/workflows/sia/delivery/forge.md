# Forge

Forge keeps Sia ready for follow-up requests in this conversation. The `Sia` prefix is optional while Forge is on.
Exact operation names and aliases stay in Forge; reserved directives and explicit `unattended` retain normal routing.
Resolve terse follow-ups from clear active context; ask when materially different interpretations remain.

Questions and read-only requests run directly. Change requests, including `do:`, follow the protocol's shared saved-plan
and approval boundary. Enabling Forge is not approval to edit. `plan:` requests planning; `inline plan` explicitly
selects an unsaved plan, still requiring approval. Remove the selector before interpreting the request.

Use the actual operation and workflow and the shared saved-plan support for saved tasks. Saved plans can be resumed
without requiring Forge to be turned off. Resume does not approve a pending plan. Inline-only tasks cannot resume in a
new conversation. Complete approved work without repeated approval; a new change request starts a new plan.

Completion clears the active task and leaves Forge ready. Off, stop, reload, or a new conversation ends Forge;
saved plans retain their status. Do not create extra Forge session artifacts.
